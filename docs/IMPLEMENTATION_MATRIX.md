> 更新日期：2026-08-01  
> 基准：当前正式仓库，不包含 `C:\Users\ASUS\Downloads` 中的外部旧近似器。  
> 重要：本矩阵评价“能否接入统一完整对局并产生正式结果”，不是评价某个局部函数是否有单元测试。

## 1. 状态定义

能力状态采用审计要求中的六类：

- `已完整实现`：完整接入权威入口并通过真实路径验收；
- `部分实现`：存在可复用代码，但覆盖范围或集成不完整；
- `仅文档存在`：正式 Knowledge 有规则，代码没有对应实现；
- `仅测试替身存在`：只有测试构造或模拟替身，没有生产路径；
- `缺失`：未发现对应实现；
- `实现错误`：现有实现与正式 Knowledge 冲突；
- `尚未接入正式入口`：数据或局部功能本身可用，但没有完整对局入口消费。

若一项同时符合多种情况，主状态取对正式运行影响最大的类别，并在证据中说明局部成果。

## 3. 必需核心类型矩阵

| 类型／接口 | 状态 | 说明 |
|---|---|---|
| `CardInstance` | 部分实现 | 已从正式逐实体 `DeckRecord` 建立不可变运行时对象并校验装备栏；尚未走完卡牌生命周期 |
| `PlayerState` | 部分实现 | 已统一玩家 ID、连续座次、体力、上限和存活不变量；尚无身份、阶段标记、技能状态等整局字段 |
| `GameState` | 部分实现 | 已统一玩家、160张实体牌、唯一位置、区域顺序、牌守恒和版本号；尚未覆盖模式、轮次、阶段、当前行动者、胜负等整局状态 |
| `EventQueue` | 部分实现 | 已提供不可变事件的单调编号和 FIFO 队列；尚无生产规则调度、插入优先级、取消和胜利终止 |

| `enumerate_legal_actions` | 部分实现 | 通用入口已存在并对未注册规则失败关闭；目前只有测试适配器，没有完整模式生产适配器 |

## 5. 武将实施门禁矩阵

门禁字段定义：

| 字段 | 通过条件 |
|---|---|
| 规则正文完整 | 平台／版本／技能原文或用户确认文本及项目结算齐全 |
| 程序实现完成 | 接入统一状态、事件、合法动作与模式，不是孤立纯函数 |
| 确定性测试通过 | 构造真实统一 `GameState` 并检查真实状态／事件变化 |
| 网页人工场景通过 | 网页调用同一核心完成代表场景 |
| AI策略完成 | AI 在完整合法动作集合中正确评价发动与不发动 |
| 反制策略完成 | 对手合法反制进入完整候选并通过审计 |
| 允许正式胜率 | 前六项和对应卡牌／模式全部通过，且失败关闭门禁为零 |

## 7. 允许与禁止的当前结论

当前可以：

- 使用正式 Knowledge 回答规则问题；
- 调用局部函数进行明确范围内的确定性计算；
- 运行组件单元测试；
- 复用 160 张牌数据做独立抽牌／概率计算。
- 构造权威 foundation 会话、移动实体牌、登记事件并校验记录完整性。

当前不可以：

- 声称正式引擎能完整运行一局；
- 声称任何模式 `unsupported=0`；
- 声称任何武将已获准正式胜率；
- 把局部 seed 当作整局可回放确定性；
- 把记录哈希链完整性称为“规则已经确定性重执行”；
- 把外部旧近似器或自证 AI 审计接入正式链路；
- 把旧结果的数值作为现行规则结论。
