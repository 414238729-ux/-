# 三国杀模拟规范

> 状态：用户整理解释  
> 数据原则：本文件不把用户提供、派生或待核验的数据描述为官方事实，也不补充用户未提供的牌或规则。

## 1. 用途与边界

本文件用于记录三国杀相关模拟所需的规则来源、结构化技能、初始状态、牌堆信息、结算顺序和待确认问题。

它不是官方规则汇编。任何实际规则或数据都必须附带来源、版本和适用模式。

本项目当前规则集、模式规则和160张实体牌堆均以三国杀移动版为主要适用平台。其他服务器或桌游版规则仅在对应章节明确说明时适用；不得因局部引用桌游版说明而把整个项目的平台改成未知，也不得静默跨平台套用。

### 1.1 资料分层

本文件只保存通用建模规范、资料导航与牌堆接口，不重复堆叠具体模式规则或逐牌效果：

- `三国杀模式规则.md`：军争身份、2v2排位、斗地主及其选将、座次、胜负与死亡奖惩；
- `三国杀基础术语与通用机制.md`：牌区、伤害、横置、距离、攻击范围与装备栏；
- `三国杀卡牌效果.md`：基本牌、锦囊、延时锦囊、武器、防具与坐骑的完整说明；
- `三国杀卡牌结构化数据.csv`：每种卡牌一条核心效果，供字段化检索；
- `三国杀卡牌使用方式.csv`：【桃】【酒】等一牌多用途的时机、目标、条件与独立次数额度；
- `三国杀牌堆数据.csv`：实体牌的花色、颜色、点数和数量，供牌堆概率计算。
- `三国杀武将规则补充.md`：本项目按需维护的指定武将技能原文、采用结算、专属策略与嘲讽口径。

卡牌定义表不包含实体牌数量，多用途表不重复卡牌全文，牌堆实例表不替代复杂效果说明；三者以 `card_key` 关联。AI策略与临时武将画像不写入任何卡牌 CSV。规则资料状态只使用：`当前确认`、`用户整理解释`、`文本推导`、`模拟假设`、`待核验`、`历史规则`、`分析约定`。

#### 证据与职责分层

发生冲突时按以下顺序读取：用户当前对话明确确认；《三国杀武将规则补充》中对应条目的当前确认结算；基础机制、模式和卡牌正式文件；本文件的分析约定。技能原文、项目采用结算、策略层和审计层必须分别保存。规则层决定时机、前置条件、合法目标、费用、次数、牌区移动与触发事件；策略层只决定是否发动、目标与分支、牌序、保留、响应、承伤和计划切换；审计层只记录候选、评分、来源和理由。任何AI策略都不得反向修改技能合法性。

### 3.2 CSV 字段

| 字段 | 含义与使用规则 |
|---|---|
| `instance_id` | 一张实体牌的唯一标识；当前正式表一行一张，不得重复 |
| `deck_id` | 一副牌堆数据的稳定标识；不同值不得直接混合 |
| `platform` | 游戏平台，计算前必须核对 |
| `mode` | 适用模式，不能外推到未记录模式 |
| `version` | 用户描述的牌堆版本，不得改写成未提供的官方版本号 |
| `effective_date` | 数据生效或记录日期，采用 `YYYY-MM-DD` |
| `card_name` | 用户提供的牌名 |
| `card_variant` | 牌的已记录变体；`EX扩展` 用于上述四张牌，其余值不应自行扩展含义 |
| `card_type` | 按牌名结构化得到的基本牌、锦囊牌或装备牌分类；属于推断，待当前版本官方核验。当前 CSV 没有宝物牌记录 |
| `suit` | 花色 |
| `color` | 由花色派生：♦、♥为红，♣、♠为黑 |
| `rank` | 点数，使用 A、2–10、J、Q、K |
| `quantity` | 当前实例表固定为 1；概率仍按该列求和，以保留通用接口兼容性 |
| `card_key` | 关联 `三国杀卡牌结构化数据.csv` 的卡牌定义主键 |
| `equip_slot` | 装备实例的规范栏位；非装备牌可留空 |
| `distance_modifier` | 具名坐骑的实际距离修正；其他牌可留空 |
| `source`、`source_type` | 初始来源及用户实卡核验过程；不等于官方发布 |
| `verification_status` | 当前统一为 `user_verified_against_actual_cards` |
| `verified_date` | 用户核验记录日期，采用 `YYYY-MM-DD` |

`color` 是由 `suit` 机械推导的结果；`card_type` 是按牌名进行的结构化分类推断。两者可以用于内部统计，但输出时必须保留其证据状态，不得称为当前版本官方逐牌核验。

### 3.3 查询与调用规则

1. 遇到抽牌、刷牌、换牌、颜色、花色、点数、牌名或牌类别概率问题，优先读取 `knowledge/三国杀牌堆数据.csv`。
2. 先使用 `deck_id`、`platform`、`mode`、`version`、`effective_date` 锁定一副牌堆，再进行统计或展开实体牌。
3. 用户没有指定版本且能匹配多个牌堆时，必须请求确认，或按版本分别计算；不得把多个牌堆合并。
4. 总牌数和各分组数量使用 `sum(quantity)`；当前实例表恰好一行一张，仍不得把“行数”硬编码为通用概率分母。
5. 不放回抽取按实体牌数量建模。计算至少一张指定牌时，目标数量是筛选后目标行的 `quantity` 之和。
6. 默认包含 `card_variant=EX扩展` 的四张牌；用户明确要求不含 EX 时才排除。
7. 用户要求“标准牌堆”“军争牌堆”或二者差异时，应先说明当前来源未标记其余记录的标准/军争归属，不能据此 CSV 作伪精确拆分。

### 3.4 校验与统计

导入或修改 CSV 后至少执行以下检查：

- 表头完整且顺序明确；`equip_slot`、`distance_modifier` 只在适用的装备实例中填写，其他必填字段去除首尾空白后均有值；
- `instance_id` 唯一，`quantity=1`，当前共160条实体牌记录；
- 同一 `deck_id` 内的平台、模式、版本和日期一致；
- 当前数据集中 `sum(quantity)=160`；
- 当前数据集中不存在宝物牌记录；未启用的虚拟牌、特殊标记和额外实体牌不得写入本 CSV；
- `suit` 仅使用 ♦、♣、♥、♠，且 `color` 与花色派生规则一致；
- 同一 `deck_id` 下不得重复使用 `instance_id`；同一实例出现不同类别、颜色或元数据时标记为冲突，不静默覆盖；
- 分别按 `card_name`、`card_type`、`color`、`suit` 分组并汇总 `quantity`；
- 单独统计空值、`待填写`、`待核验` 和有冲突记录，不能只报告“没有空字段”。

### 3.5 缺失数据与精度

若相关记录缺少花色或点数：

- 不得把缺失花色归入任一已知花色，也不得由未知花色推导颜色；
- 不得把缺失点数归入相邻行或任一点数；
- 只依赖牌名且牌名与数量完整的问题，仍可在说明字段覆盖范围后计算；
- 花色、颜色或点数概率只能对字段完整的子集给出条件结果，或根据未知数量给出上下界；
- 若缺失值可能改变用户要求的全牌堆概率，应明确写出“当前资料不足以给出全牌堆精确值”。

当前四张 EX 牌的花色与点数已经由用户明确确认，不属于缺失字段；不得再次按排版位置将其标为未知。

## 4. 分析术语

- **规则原文**：来源中可逐字核对的内容。
- **规则解释**：从原文推导出的结算含义，不等同于官方裁定。
- **计算假设**：为模拟补充的初始状态、策略或随机模型。
- **事件**：能够进入触发检查的状态变化或结算节点。
- **时点**：事件之前、期间、之后或更细的结算位置。
- **状态**：角色、卡牌、区域、标记、资源及其他会影响后续结算的信息集合。
- **资源**：会被消耗、获得、占用或限制使用次数的量。
- **合法目标集合**：在指定状态下满足全部选择条件的对象。
- **结算队列**：需要按顺序处理的效果集合。
- **截断**：模拟因预设硬上限停止，而非规则自然终止。

## 5. 已确认的结算建模约束

本节只记录会直接影响模拟接口和状态机的约束；完整规则说明仍以 `三国杀基础术语与通用机制.md` 和 `三国杀卡牌效果.md` 为准。

### 5.1 牌的区域与移动术语

1. 通用描述中单独写“牌”时，可选范围为手牌区和装备区，不包括判定区。
2. 写“区域内的牌”时，可选范围为手牌区、装备区和判定区。
3. 具体卡牌或技能另有区域限制时，以该具体描述覆盖通用范围。
4. 模型必须分开记录“弃置”“失去牌”“置入弃牌堆”和“重铸”；卡牌进入弃牌堆不自动表示某名角色执行了一次弃置牌操作。
5. 建议移动事件至少保留 `from_zone`、`to_zone`、`move_reason` 和 `acting_player`；没有执行弃置的角色时，`acting_player` 不得伪造。
6. 【贯石斧】的两张牌只能来自使用者的手牌区和装备区，可以是两张手牌、两张装备或各一张，不能来自判定区。

### 5.2 【无懈可击】与延时锦囊

1. 【无懈可击】可抵消锦囊牌对一名角色产生的效果，不限于伤害、负面或敌方锦囊。
2. 多目标或全体锦囊逐名目标处理；一张【无懈可击】只抵消该锦囊对当前对应角色的效果，其他角色继续结算。
3. 【无懈可击】可以被另一张【无懈可击】抵消；响应长度由合法响应和实际持牌情况决定，不设置与实际状态无关的人为张数上限。
4. 延时锦囊被使用并进入判定区时不进入【无懈可击】响应时机；到当前角色判定阶段、即将进行该牌的判定并决定其是否生效之前，才进入该响应时机。
5. 延时锦囊的统一处理次序为：读取判定区中的牌 → 进入判定前【无懈可击】时机 → 被抵消时按该牌规则决定去向，或未被抵消时进行判定 → 完整处理判定结果和效果 → 按该牌规则置入弃牌堆或移至其他角色判定区。
6. 选择延时锦囊的使用目标时，必须检查目标判定区：同一角色不能同时存在两张或更多同名延时锦囊；不同名称可以共存。技能直接置入判定区时也默认不得形成同名共存状态。
7. 角色跳过整个判定阶段时，判定区内延时锦囊本回合全部留存：不进入判定前【无懈可击】时机、不判定、不产生效果，也不因跳过阶段而置入弃牌堆或转移；未来实际经过判定阶段时再结算。留存期间仍可被其他明确效果移动。

| 延时锦囊 | 被【无懈可击】抵消 | 未被抵消后的判定与去向 |
|---|---|---|
| 【乐不思蜀】 | 不判定、不跳过出牌阶段，置入弃牌堆 | 红桃时不跳过、非红桃时跳过出牌阶段；两种结果均置入弃牌堆 |
| 【兵粮寸断】 | 不判定、不跳过摸牌阶段，置入弃牌堆 | 梅花时不跳过、非梅花时跳过摸牌阶段；两种结果均置入弃牌堆 |
| 【闪电】 | 不判定、不造成伤害，移至当前角色下家的判定区 | 黑桃 2 至 9 时造成 3 点雷属性伤害，完整处理伤害、技能、濒死和死亡后置入弃牌堆；其他结果不造成该伤害，移至下家判定区 |

“下家”按结算时有效的当前存活角色环确定：从当前角色开始沿座次数递增方向寻找下一名仍在游戏中的角色，跳过死亡座次，超过最大座次数后回到最小座次；角色交换位置后使用交换后的当前座次。表中的“置入弃牌堆”只记录移动事实，不得自动生成“某名角色弃置牌”的事件。

### 5.3 横置与属性伤害传导

1. 只有横置角色实际受到大于 0 点的火属性或雷属性伤害才开启一轮传导；无属性伤害不触发传导，也不解除横置。
2. 原始受伤角色最终实际受到的属性伤害点数记为 `chain_base_damage`；其实际受伤后解除横置，并从该轮后续传导对象中排除。
3. 剩余传导顺序以当前回合角色为锚点，按座次数递增方向循环；不从原始受伤角色、伤害来源或卡牌使用者开始排序。
4. 每处理一名候选角色前重新检查其是否仍横置；已中途解除横置者跳过。
5. 当前角色从 `chain_base_damage` 开始应用其自身效果，所得最终点数记为 `recipient_actual_damage`。局部增减默认只影响该角色；只有明确修改后续传导基础值的效果才能改变 `chain_base_damage`。
6. 传导伤害继承原始伤害来源；不得把【铁索连环】、横置状态或受伤角色本人设为新伤害来源。
7. 一名角色实际受到大于 0 点传导伤害后解除横置，并完整处理伤害、技能、体力、濒死、死亡及相关效果，再处理下一名角色。
8. 原始伤害或任一后续传导伤害被完全防止、最终为 0 时，该角色保持横置，不进入受到伤害后的流程，本轮传导立即终止。
9. 传导过程中产生的新火属性或雷属性伤害是独立伤害事件；满足条件时开启独立的新传导，完整处理后再返回原传导，并继续动态检查剩余角色。

### 5.4 【丈八蛇矛】转化字段

【丈八蛇矛】把两张手牌转化为普通【杀】时：两张均红则 `color=红`，两张均黑则 `color=黑`，颜色不同则 `color=无色`；无论原牌颜色、花色和点数如何，转化牌均为 `suit=无花色`、`rank=无点数`，不得继承、合计或另行生成花色与点数。转化牌默认是普通【杀】并造成无属性伤害，其他效果明确转换时再按其规则处理。颜色、花色、点数与伤害属性必须作为不同字段建模。

### 5.5 实际距离与攻击范围

1. 模型必须分开计算“实际距离”和“攻击范围”，不得共用一个可互换的数值。
2. 实际距离由事件发生时的当前座次基础距离、攻击坐骑、防御坐骑和其他距离修正共同决定；位置交换后必须按当前座次重新计算。
3. 攻击范围由默认范围、武器和明确修改攻击范围的效果决定；武器只参与攻击范围计算，除非具体武器或技能明确同时修改实际距离。
4. 文本只写“距离”或“距离为 X”时，调用实际距离判定；只有明确写“攻击范围内”时，才调用攻击范围判定。【杀】及具体效果另有专属规则时按其规则处理。
5. 【顺手牵羊】和【兵粮寸断】必须调用同一个实际距离函数，且仅在“使用者与一名其他角色的实际距离为 1”时判定目标合法；不得调用攻击范围判定这两张牌的目标。
6. 建议通用接口分为 `get_actual_distance(source, target, state)` 和 `is_in_attack_range(source, target, state)`；两者应分别保存中间值与修正明细，便于说明合法性。
7. 通用多人距离以“当前存活且仍在游戏中的角色环”为基础：保留角色当前座次编号，但从环中跳过死亡角色；死亡角色两侧最近的存活角色随即成为相邻角色。
8. 基础距离应先建立按当前环形顺序排列的存活角色列表，计算两名目标沿座次数递增与递减两个方向所需的存活角色间边数，再取较小值。不得直接把包含死亡座位的原始编号代入 `min(abs(i-j), N-abs(i-j))`；只有索引已重映射到存活角色环时才能使用等价公式。
9. 技能交换位置后，按事件发生时的当前座次和当前存活环顺序重算；死亡角色不获得普通回合，也不参与通常的响应、救援或距离关系，具体死后技能明确例外时除外。

### 5.6 未注明的伤害属性与来源

1. 卡牌或技能只写“伤害”而未注明属性时，默认记为无属性伤害；该规则也适用于技能生成或加入游戏的特殊卡牌。
2. 单独的“伤害”作为适用条件时，覆盖无属性、火属性和雷属性伤害；“失去体力”不是伤害，必须用独立事件类型建模。
3. 卡牌伤害未注明其他来源时，默认以卡牌使用者为伤害来源；多目标、全体锦囊和技能生成的特殊卡牌也适用。
4. 【南蛮入侵】和【万箭齐发】默认造成 1 点无属性伤害，伤害来源为使用者。【闪电】造成的伤害没有伤害来源，是明确例外。
5. 卡牌或技能明确指定其他属性、来源或无来源时，覆盖上述默认值；铁索连环传导伤害继续继承原始伤害来源。

### 5.7 【火攻】、【藤甲】与【白银狮子】的建模边界

1. 【火攻】使用时只能选择至少有一张手牌的角色；结算到展示步骤时若目标已无手牌，本次结算直接结束，不能从装备区或判定区选牌代替。
2. 【藤甲】先判断普通【杀】、【南蛮入侵】或【万箭齐发】是否对目标无效。普通【杀】只有在该判断前已转换为属性【杀】，才不受此无效效果影响；仅在伤害阶段修改属性，不能令已无效的牌重新生效。
3. 【南蛮入侵】与【万箭齐发】被【藤甲】判定为无效后，不进入伤害结算；后续属性转换不能令它们恢复生效。防具被无视、失效或已离开装备区时，再按正常规则结算。
4. 【藤甲】的火属性伤害 `+1` 是伤害修正；【白银狮子】使装备者将受到的 2 点或更多伤害改为 1 点，适用于全部伤害属性、有来源或无来源伤害和传导伤害，但不适用于失去体力。
5. 【白银狮子】以任何方式离开装备区时，装备者恢复 1 点体力，但不能超过体力上限。模型应依赖“从装备区离开”这一区域移动事件，不得仅为弃置或替换操作生成回复。

### 5.8 牌堆不足、弃牌重洗与检索

#### 摸牌与重洗

**状态：当前确认**

1. 摸牌、观看牌堆顶、亮出牌堆顶或判定取牌时，若当前牌堆不足以完成操作，立即把弃牌堆中当前能够参与重洗的全部牌洗混为新牌堆，再继续尚未完成的部分。
2. 可以先逐张取得原牌堆现有牌，耗尽后重洗，再取得剩余数量；其他实现只有在最终抽取概率、卡牌归属和结算时点完全等价时才可采用。
3. 只有已经实际位于弃牌堆中的牌参与重洗。正在使用或结算的牌，以及手牌、装备区、判定区、武将牌上的“权”、技能特殊区域、移出游戏或被效果保留的牌均不进入本次重洗。
4. 正在结算的牌只有完成结算并实际置入弃牌堆后，才可能参与之后发生的重洗。
5. 若重洗后仍需要继续摸至少一张牌，却无法取得下一张牌，游戏立即平局。若效果要求的牌已经全部取得完毕，即使取得的是最后一张，也不导致平局；不得采用“只摸实际剩余数量后继续游戏”的旧解释。
6. 该结论必须通过 `draw_exhaustion_rule` 返回，资料状态固定为【当前确认】。

#### 观看、亮牌与判定彻底不足

**状态：分析约定**

观看牌堆顶、亮牌或判定经过重洗后仍不足以完成操作时，当前暂按游戏平局处理。这是用户指定的当前暂定规则，资料状态仍为【分析约定】，必须通过 `non_draw_deck_exhaustion_assumption` 返回并在样本或报告中披露；不得与“摸牌彻底不足即平局”的【当前确认】混写，也不得用一个无状态来源的“无牌即平局”规则覆盖两者。后续若用户提供更精确规则，应单独替换这一约定。

#### 检索特定类别牌

**状态：当前确认**

1. “从牌堆中获得、寻找或检索某种特定类别的牌”只检查当前牌堆。
2. 当前牌堆没有符合条件的牌时，记录检索失败或按效果文本结束，不因检索失败把弃牌堆洗入牌堆；即使弃牌堆存在目标牌也不重洗。
3. 具体技能明确要求检查弃牌堆、全部卡牌或重新洗牌时，才按该特殊规则处理。

### 5.9 多张延时锦囊的顺序字段

**状态：当前确认**

1. 同一判定区内不同名称的延时锦囊可共存，同名牌仍须在置入或选目标时拒绝。
2. 每张牌保存其进入当前判定区时的单调递增 `judgment_zone_entry_index`；结算时按该字段降序处理，即后发先至、后进先出。不得按牌名、花色、牌堆顺序或固定类型排序。
3. 每次调用单张结算器时，必须完整包含对应的【无懈可击】响应、判定、效果、去向，以及由此产生的技能、伤害、濒死、死亡与胜负检查；只有游戏尚未结束时才调用下一张。
4. 【闪电】转移离开当前角色判定区后，本张结算完成；若游戏未结束，继续处理当前判定区的下一张。
5. 跳过整个判定阶段时不调用单张结算器，全部牌及其进入索引原样保留。位置交换不重写进入索引；仅在具体卡牌需要确定当前下家时查询当时座次。

### 5.10 模式变体、身份历史与隐藏信息

本节只规定状态接口和资料路由；移动版八人军争“主公立储、内奸择途”特殊玩法的完整立储、继位、身份转换和野心家规则，必须查询 `三国杀模式规则.md`。

#### 模式隔离

**状态：当前确认**

1. 八人军争模拟必须显式记录 `mode_variant`。只有 `mode_variant = mobile_8p_heir_and_spy_choice` 时，才能加载该限时变体的状态、事件、技能和覆盖规则。
2. 未设置该值，或明确采用标准八人军争时，不得出现立储、储君死亡效果、储君继位、内奸择途、转化忠臣、野心家或野心家标记。
3. 每次输出都应报告实际采用的 `mode_variant`，不得把标准八人军争与限时变体的结果合并为一个样本分布。
4. `mobile_8p_heir_and_spy_choice` 已确认复用 `deck_id=sgs_mobile_non_special_20260725_unofficial`；模式开关只改变身份与状态机，不复制或扩充牌堆。其他未记录变体仍须单独确认其 `deck_id`。
5. 普通八人军争是当前默认八人测试分支，使用主公1、忠臣2、反贼4、内奸1；若普通分支的反贼胜率明显过高，只另开限时玩法独立测试，不得将两种模式的结果合并。

#### 身份与当前主公

**状态：当前确认**

1. 角色至少分别记录 `role_original` 与 `role_current`：前者在开局后保持不变，仅用于日志和分析；后者在身份转换正式生效时更新，并用于之后的身份效果、击杀奖惩、死亡公开和胜负判断。
2. 待生效的身份选择只写入独立的 pending/locked 状态；在正式生效时点前不得提前修改 `role_current`。
3. 择途选择锁定后只等待下一次实际发生的合法存活角色回合开始事件，不保存某个预定生效玩家标识。预期下家死亡不会产生事件，连续死亡则持续等待；人数条件变化不重新检查，游戏先结束或选择者先死亡则不转化。
4. 主忠胜负判断使用 `role_current`：当前主公存活且没有存活反贼、内奸或野心家时才胜利。未生效择途仍是内奸，已转忠者按忠臣，已转野心家者按野心家。
5. 建议把 `original_lord_player_id`、`current_lord_player_id` 和 `seat_number` 分开保存。继位只更新当前主公及相关身份状态，不调用全场重新编号或排序函数，也不把新主公移动到原 1 号位。
6. 继位后，回合顺序、实际距离、多人响应、濒死救援、改判及其他座次关系继续使用未重新编号的当前座次与存活角色环；新主公不会仅因继位立即获得额外回合。

#### 隐藏信息与决策视图

**状态：当前确认**

1. 模型应把“真实状态”“公开事件”和“各角色可见信息”分开保存。建议为隐藏状态记录 `information_owner`、`known_to`、`event_announced` 与 `subject_revealed`，不能用一个布尔值同时代表事件公开和对象公开。
2. 储君目标的具体可见范围、转化事件的公告范围、转换者是否公开以及新主公身份是否公开，均从匹配的模式规则生成角色视图；不得让决策策略直接读取全局真实状态。
3. 正常模拟中，每名角色只能基于其当前可见视图行动。全知策略只能作为单独的模拟假设运行，并须与正常隐藏信息结果分开报告。
4. 非卡牌的特殊标记应作为独立资源容器维护；虚拟牌应记录其 `virtual=true`、产生效果和已明确的牌属性，不得伪造实体来源区域或实体牌移动。
5. 标准身份局同样执行该可见视图：AI不能读取未公开的忠臣、反贼或内奸身份，也不能读取未公开手牌；只能根据公开使用、打出、弃置、获得、已知转移、合法观看、响应读条及其他公开行为建立概率判断。
6. 2v2队友完整手牌依法互相可见；敌方手牌仍隐藏。斗地主三方不共享手牌。真实无懈窗口产生全场可见的可用性知识；农民花/蛋仅用于公开具体场景YES/NO问答，不回答按UNKNOWN。两套机制独立，详见[三国杀AI信息规则](三国杀AI信息规则.md)。

3. 现有叫价规则确定最终地主后，不移动任何玩家：地主标为1号位，物理环中地主的下一名标为2号位，上一名标为3号位。
4. 叫价倍数只参与最终地主判定，不直接参与座次映射。相同物理顺序与相同地主必须始终生成相同座次。
5. 生成完整过程后，后续行动、距离、救援和响应使用确定的当前座次；不得再随机交换两名农民，也不得再抽取一个50%分支。
6. 固定阵容模拟若已提供物理座位与最终地主，同样直接使用确定映射；候选框、断线或武将权重均与此座次步骤无关。

**简化状态：模拟假设**

1. 仅在未显式模拟物理座位、首名叫地主者和叫价策略，且三名玩家完全对称时，可将某个指定农民落在2号位或3号位的边际概率各记为50%。
2. 输出标记为【计算假设：未显式模拟叫地主过程时的边际对称近似】。这不是地主确定后的实际随机分配规则；任一完整过程字段已知时都不得再次采用。

#### 武将候选概率

**实际分布状态：当前确认**

1. 客户端合法武将的实际出现概率不是等概率，具体权重未知；不得写成“是否等概率未知”或“客户端默认均匀随机”。

**无实际权重时的状态：模拟假设**

1. 确实需要随机生成候选时，在当次规则允许的合法候选事件之间等概率抽取，同时保留现有的重复、放回和排除规则。
2. 输出必须说明：“本次武将候选概率采用等概率计算假设，不代表客户端真实出现权重。”
3. 用户直接固定参战武将或阵容时，不模拟这些武将的刷出概率；候选概率假设不得进入已固定阵容的对局胜率。

#### 固定阵容与按需武将画像

**状态：分析约定**

完整三国杀移动版武将技能与全部特殊问答数据库不是固定阵容模拟的前置条件。纯牌堆、卡牌和模式机制可直接运行；用户指定参战武将并提供或确认技能文字后，只为本次参战者创建临时画像。缺失的技能交互只限制受影响的分支，不得表述成整个固定阵容模拟无法进行。

画像至少保留 `general_name`、`base_hp`、`base_max_hp`、原始 `skill_text`、`skill_version`、本次 `parsed_skill_rules`、`strength_tier`、`defense_value`、`on_damage_benefit`、`retaliation_risk`、`burst_threat`、`control_threat`、`growth_threat`、`hand_dependency`、`equipment_dependency`、`kill_difficulty`、`special_interactions`、`source`、`confidence` 与 `unresolved_interactions`。不得凭模型长期记忆补齐空字段；未提供部分明确列为缺口，已确认且不依赖该缺口的部分继续模拟。新增或重做武将只更新当次画像，不要求同步维护第二套完整AI数据库。

用户比较一组武将且未说明强弱时，默认其静态综合强度大致相同；主要按卖血、防御、当前体力与手牌、即时威胁和击杀效率排序。只有用户明确给出较弱、中等、较强或明显高于档位时，才应用对应静态修正。

#### 死亡、胜利与身份奖惩状态机

**状态：当前确认**

1. `meets_normal_death_condition` 只在全部合法濒死救援完成且体力仍低于 1 时返回真；它只表示满足通常死亡条件，不得同时清空区域、公开死亡身份或移出存活环。
2. 之后依次调用 `before_formal_death_overrides`。没有模式覆盖时该列表为空；八人特殊玩法的当前主公在此完成合法储君检查，且此时原主公区域牌仍存在。
3. 存在合法储君时，死亡前覆盖先处理从原主公区域内获得至多 1 张牌、新主公身份公开、当前主公更新、体力上限增加、回复体力和新主公自身主公技启用；不存在合法储君时覆盖检查不改变主公状态。
4. 只有全部死亡前覆盖完成后，才调用 `confirm_formal_death`，随后调用 `after_formal_death_events` 处理死亡身份公开、剩余牌去向、退出游戏及其他依法发生在正式死亡后的事件。
5. 完成当前身份、当前主公及其他胜负前置状态更新后调用 `check_victory`。继位不是可在胜利后补做的击杀奖励；不得先判反贼胜利或先清空原主公区域再继位，也不得先确认其正式死亡再尝试继位。
6. 胜利成立时立即终止游戏，不再生成或执行击杀反贼摸 3 张、主公击杀忠臣弃牌、野心家击杀可选摸 3 张等身份奖惩事件，也不再调用尚未开始的铁索传导、全体锦囊目标、额外伤害或后续回合。
7. 因胜利而跳过的奖励摸牌不能触发重洗、牌堆耗尽或平局，也不能覆盖已经成立的胜利结果。
8. 只有胜利检查返回“游戏继续”时，才处理身份击杀奖惩并继续下一段连续结算。具体武将死亡技能继续依照其自身明确时序；本状态机不无依据删除或统一重排其他死亡技能。

### 5.11 锦囊通用时机与结构化继承

**状态：当前确认**

1. 除【无懈可击】外，普通主动锦囊和延时锦囊的有效基础时机为 `trick_play_phase`，即使用者自己的出牌阶段；基础次数为 `unlimited`，但每次仍检查合法目标、实体牌或合法转化及卡牌自身条件。
2. 【无懈可击】的具体时机为 `trick_response_window`，`response_only=true`；没有合法锦囊响应窗口时不能主动使用。它的基础次数同样为 `unlimited`。
3. 结构化记录优先读取非空 `specific_timing`；该字段为空时必须读取 `inherits_generic_timing`。二者均为空或继承值为 `false` 且没有具体时机时应报错，绝不能解释为任意时机。
4. `base_use_limit` 明确基础次数，`inherits_generic_use_limit` 记录是否继承通用次数，`skill_override_allowed` 只表示技能可以明确覆盖。没有具体技能覆盖时，仍按基础规则。
5. CSV 的人类可读 `use_timing` 与 `use_limit` 应和上述解析结果一致；详细卡牌特例仍以《三国杀卡牌效果》为准。

#### 桃、酒与装备牌的用途和事件字段

**状态：当前确认**

1. 【桃】【酒】和装备牌的结构化记录必须明确 `use_context`、`default_timing`、`base_use_limit`、`response_window`、普通卡牌响应、技能无效化及无效后的事件语义；空值或“未提供”不得解析成任意时机、无限次数或可被任意响应。
2. 【酒】在 `三国杀卡牌使用方式.csv` 中分开保存 `dying_self_rescue` 与 `play_phase_slash_buff`：前者无基础次数限制且不消耗后者额度；后者每个独立出牌阶段限一次。获得新出牌阶段时新建额度状态。
3. 【桃】在同一用途表保存三个互不共享额度的上下文：`own_play_phase_self_heal`、`dying_self_rescue`、`rescue_other_dying_character`。三者 `limit_count` 均为 `unlimited`，并分别记录 `timing`、`target_scope` 与 `condition`；不得把“无限制”解释成可以绕过时机、目标、受伤或濒死条件。卡牌定义表中的旧 `use_modes` JSON 留空，避免两个事实源漂移。
4. 装备牌的主动使用继承 `equip` 通用规则：`default_timing=own_play_phase`、`base_use_limit=unlimited`、`response_window=none`；技能明确覆盖时机时另行记录。装备效果若文字没有次数限制，则每次满足触发与支付条件时均可发动或生效，不得自动补成“每回合限一次”；程序循环保护上限必须单独报告为截断，不是规则次数。
5. 对上述牌，普通卡牌响应恒为假，【无懈可击】不能响应；明确技能无效化时仍生成 `card_used`，但不生成 `card_effect_resolved` 与 `after_card_effect_resolved`。
6. 事件序列至少分为 `card_use_declared`、`card_use_cost_paid`、`card_used`、`before_card_effect_resolution`、`card_effect_invalidated`、`card_effect_resolved`、`after_card_effect_resolved`。仅要求使用成立的触发读取 `card_used`；要求效果完成的触发读取最后两个结算事件。
7. 装备牌被技能无效时不进入装备区、不触发装备成功事件；实体牌最终去向由具体无效化规则决定，资料未明确时保持未知。
8. 结构化布尔字段使用 `true`、`false`、`unknown_or_not_applicable` 三值语义；空字符串保持未知或不适用，不得自动转成 `false`、0次或无限制。解析优先级为卡牌特例、通用类型规则、模式覆盖、武将技能覆盖，仍不能确定时继续保持未知。

### 5.12 【铁索连环】理性AI计算策略

**状态：分析约定**

本节是决策策略，不是【铁索连环】或【火攻】的强制卡牌效果。AI不得随机横置角色，应比较以下合法候选的团队预期净收益：只横置敌方并建立敌方传导网络；直接火攻敌方；将自己作为属性伤害入口的自我引火；将队友作为入口的友军引火；不建立组合并保留或重铸【铁索连环】。

1. 敌方横置通常用于让一次属性伤害命中多个敌方；已有友军处于危险横置状态时，也应考虑解除其横置。若己方反向受伤风险更高，可以放弃用牌。
2. 自我引火须核对自身火攻是否合法、展示牌与另一张同花色弃牌是否来自不同实体牌、自身实际承伤、藤甲增伤、濒死与救援成本、卖血收益及敌方免疫或受伤收益。初始属性伤害被防止或减为0时不传导。
3. 友军引火须核对队友有手牌、火攻花色匹配概率、队友承伤与卖血收益、濒死风险、救援资源，以及传导是否能击杀或限制关键敌人。队友信息不足时按概率计算；不得自动按100%。
4. “稳定传导”只表示入口已经实际受到大于0点属性伤害、敌方在其传导时点仍横置且游戏尚未结束后，传导不再要求敌方出【闪】或重新进行火攻展示与花色匹配；伤害防止、解除横置、减伤和提前胜利仍可改变结果。
5. 团队收益至少计入敌方预期体力损失、击杀与行动限制、多目标价值、己方受伤技能收益，并扣除己方体力和死亡风险、救援与卡牌成本、敌方受伤收益、失败概率及后续反向属性伤害风险。选择净收益最高的合法方案；全部为负时保留或重铸。
6. 2v2可使用队友可见手牌；斗地主不能读取另一名农民的隐藏手牌。身份局只能基于公开身份、公开行为和合法概率推断分类敌我；全知身份或全知手牌分析必须单独标记为【计算假设】，不得冒充正常实战信息。
7. 传导逐名动态检查；若某名角色死亡后胜利已经成立，立即停止尚未开始的传导。是否找到能在传导途中改变横置状态的具体武将案例，不影响当前动态状态机。
8. 已经存在主要集火目标时，铁索、直接火攻、自我引火和友军引火应把对该目标的击杀概率与团队净收益纳入比较；不得为了制造无关的多目标伤害而放弃更高价值的主要击杀路线。主要目标的产生和切换按第5.13节处理。

### 5.13 集火与攻击目标选择AI策略

**状态：分析约定**

本节属于理性AI的计算策略，不是卡牌效果或模式基础规则。2v2、斗地主等阵营明确的场景默认建立一名主要集火目标，把可用单体伤害、削弱与组合资源优先投入该目标，以尽快形成实际减员；不得仅因两名敌人都可攻击就轮流或平均分配伤害。AOE、铁索传导等自然影响多人的效果仍可正常使用，但其后的单体资源仍应服务主要击杀目标。身份局必须先满足第5.13.5节的信息限制。

#### 5.13.1 动态目标评分

目标评分不得只读取固定武将排名。每名候选至少记录并动态更新：

- `static_threat`（兼容旧字段 `static_power`）：静态综合强度修正，只是输入之一；
- `current_threat`、`immediate_lethal_threat`：当前局面威胁及下一行动的致命威胁；
- `kill_probability`、`expected_resources_to_kill`、`expected_turns_to_kill`：近期击杀概率、资源与回合成本；
- `kill_efficiency`、`defense_cost`（兼容旧字段 `defensive_value`）、`rescue_cost`：击杀效率以及防具、防御、减伤、救援、转移与复活等成本；
- `on_damage_benefit`、`retaliation_risk`、`post_failure_threat`：卖血、反制及未击杀后的反扑；
- `growth_threat`、`hand_dependency`、`resource_readiness`：发育上限、手牌依赖及当前资源是否接近爆发阈值；
- `focus_accessibility`、`team_focus_support`、`focus_continuity`：当前距离、合法目标条件、队友能否加入及继续既有集火的价值；
- `death_effect_risk`、身份击杀奖惩及 `victory_progress_value`：死亡效果、身份成本与胜利推进；
- `hand_based_threat_bonus`：手牌依赖型武将因资源增长产生的额外威胁；手牌多可同时提高防御成本与技能威胁；
- `target_priority_score`：以上因素合并后的当前可执行优先级。

建议结构为：

```text
目标优先级 =
  预计击杀与人数优势价值
  + 当前即时威胁与克制价值
  + 阻止成长与资源爆发价值
  + 近期击杀概率与队友集火效率
  - 预计击杀资源与回合成本
  - 防御与救援成本
  - 卖血、反制与未击杀反扑风险
  - 危险死亡效果与身份惩罚
  - 当前不可达成本
```

实现可以使用分层判断或不同权重，但必须覆盖上述正负因素。`theoretical_priority_target` 表示忽略当前可达性后的理论高优先级目标；`primary_focus_target` 必须是当前合法且有正收益的实际集火目标。不可达的高威胁角色不能被假装成已经遭到集火。

没有实测拟合时使用透明的首版参数：较弱/中等/较强/明显高于档位的静态修正依次为 `-0.8/0/+0.8/+1.6`；每少1点体力 `+0.45`；手牌低于4张每少1张 `+0.15`，高于4张每多1张 `-0.15` 以表示更难击杀；轻/中/强防御成本为 `0.4/0.8/1.4`；轻/中/强卖血成本为 `0.4/0.9/1.5`；本轮高概率击杀 `+2.5`；下回合致命威胁按强度加 `1.5` 至 `3.0`；保持已锁定目标 `+0.4`。手牌依赖型武将每张超过基准的手牌另加 `0.15` 至 `0.4` 威胁，首版取 `0.25`。这些都是【可调计算参数】，每次报告必须回显实际参数和关键理由，不得称为官方AI权重。

#### 5.13.2 常见比较与紧急覆盖

1. 两名敌方综合强度和当前威胁接近时，通常优先选择防御、救援和预计资源成本较低者，以更快形成减员；不能仅凭“无防御”虚构额外威胁。
2. 两名敌人都缺乏防御时，强度和实际威胁明显更高者通常优先；但另一目标已接近必杀时，可以先完成即时击杀，不能为理论最强目标放弃近乎确定的减员。
3. 高防强者与易杀弱者没有固定答案：强者威胁尚未形成且弱者可迅速击杀时先杀弱者；强者下一行动可能致命、当前可以一轮击杀或即将完成关键胜利条件时优先处理强者；攻击强者只会送出大量收益且短期杀不掉时，使用控制或先杀弱者。
4. 卖血角色不是绝对禁攻目标。能以集中爆发直接击杀时，减员收益可以高于卖血收益；无法完成击杀时，应把摸牌、标记、控制、低体力强化和下回合反扑作为显著成本，优先集中爆发、控制/拆牌或暂不攻击，避免零散每回合造成1点伤害。
5. 手牌依赖或发育角色按当前资源评估：空手且短期无法恢复时威胁可暂时下降；资源较多、即将行动或接近爆发阈值时提高优先级；长期成长极强者即使暂弱也不能永久忽略，可先拆牌或控制再处理其他目标。
6. 某敌人下一行动有较高概率击杀己方关键角色、完成不可承受爆发或使己方失去攻击窗口时，`immediate_lethal_threat` 可以覆盖通常的“先杀易杀者”。
7. 击杀会触发危险死亡技能、身份惩罚、储君/继位或复活时降低评分；击杀能够立即满足胜利条件时显著提高评分，但仍先执行对应死亡与胜负前置状态机。

#### 5.13.3 主要目标锁定与切换

选择目标后记录 `primary_focus_target` 和 `focus_target_lock`。只要该目标仍存活、可合法触及、队友仍能配合且存在合理近期击杀前景，不因另一目标暂时更容易受到1点伤害或评分小幅波动而切换。

仅在以下状态变化后重新比较并记录 `focus_target_switch_reason`：

- 原目标死亡、离场或暂时不可合法攻击；
- 原目标获得极强防御，近期已难以击杀；
- 另一目标进入高概率即时击杀状态；
- 另一目标形成致命即时威胁；
- 原目标的卖血、反制或未击杀反扑令继续投入转为负收益；
- 队友无法继续配合集火；
- 胜利条件、身份信息或阵营判断发生变化。

锁定不是机械坚持：必须比较继续利用已有伤害成果与放弃沉没投入的代价。重算事件包括体力、手牌或装备、技能或标记、回合顺序、濒死或死亡、距离、队友集火能力、已知救援资源及胜利/身份状态变化。

#### 5.13.4 单牌行动服从总体目标

- 【杀】与【决斗】等单体伤害优先投入主要目标；
- 【顺手牵羊】、【过河拆桥】优先拆除主要目标的防御、救援或关键资源；
- 【乐不思蜀】、【兵粮寸断】等控制可以作用于另一名致命威胁，保护对主要目标的集火过程，不要求所有牌都指向同一角色；
- 【铁索连环】、【火攻】、自我引火与友军引火必须比较其对主要目标的击杀贡献和团队净收益；
- 【桃】及其他防御资源应考虑是否需要保留，以维持己方继续集火的能力；
- 主要目标当前不可达时，可以攻击当前合法目标，也可以保留资源、调整距离或控制理论高优先级目标；不得绕过距离、目标、次数或牌源条件。

单体资源的默认分配是集中而不是轮流；多目标锦囊和自然传导不属于“错误平均分配”，但不能成为忽略主要击杀目标的理由。

#### 5.13.5 信息边界

2v2和斗地主阵营公开，可据此判断敌我。2v2队友手牌依法可见，斗地主不读取队友隐藏手牌。无懈可用性从真实响应窗口公开观察，农民协作使用具体公开问题的实际YES/NO/NO_RESPONSE；禁止自动桃状态、通用杀数共享或将保护意愿解释为确定私牌。身份局只依据公开身份、行为和合法概率推断；未知资源不得填全知真值。全知分析单列为模拟假设。信息口径以[三国杀AI信息规则](三国杀AI信息规则.md)为准。

#### 5.13.6 可解释日志

每次建立、保持或切换主要目标时，输出至少包含：目标、主要正向因素、主要成本、是否锁定及切换原因。例如：“选择集火角色B：两名敌人当前威胁接近，但B防御与预计击杀资源较低。”“暂不攻击角色A：当前无法完成击杀，伤害会给予高价值卖血收益。”“切换至角色B：B将在下一回合形成致命威胁。”不得只输出无字段含义的抽象总分。

### 5.14 团队救援、公开场景问答与无懈知识

**状态：分析约定**

#### 5.14.1 队友救援

2v2按可见完整手牌统计双方可对濒死者使用的【桃】、濒死者自己的【桃】【酒】及明确合法的技能资源；非濒死队友的【酒】不能救人。斗地主只按自己已知资源、本次明确桃事实问答的最低保证量和公开技能资源规划，不读取隐藏张数。合法已知资源足以使明确队友恢复至至少1点体力时默认必须救援，普通“留桃”理由不能放弃确定可救活的队友；选择总资源成本最低且不超额回复的顺序，达到1点后立即停止。胜利已成立、目标并非真实队友、牌被禁用或救援会立即导致己方失败时，按明确覆盖规则处理。

斗地主桃/救援只能用明确本次问题的实际公开答案：“是否至少有一张桃”属于资源事实，YES只确认当时至少一张；“是否希望救援”是行动建议，不表示任何私牌事实。NO_RESPONSE不是NO。使用或未知手牌变化后旧答案过期，不能自动刷新成共享桃状态。

鲍信协作仅围绕当前公开分发方案确认具体命题。YES确认该命题，NO只否定命题，不推出真实数量。禁止通用farmer_slash_count_signal、teammate_slash_count查询或自动共享当前杀数；同一隐藏状态下的枚举/二分/编码探测由本AI建模约束阻止，不宣传为官方互动次数。

#### 5.14.2 无懈响应读条知识

首次真正进入无懈响应窗口之前，公共资格表为UNKNOWN，不扫描隐藏手牌。窗口出现时直接抽象客户端最终依法可判断的结果，向全场发布逐角色KNOWN_USABLE/KNOWN_NONE，记录来源、窗口与时点；无UI运行层不复刻显示/点击/消失过程，也不增加不存在的窗口。已知有资格者不响应不消耗无懈；没有资格者的普通PASS不能伪造曾有资格。

无懈自身产生的后续响应窗口也是新观察机会。使用一张先使剩余量未知，不能推断用尽；新窗口按真实资格刷新。有/无知识在摸取或获得未知牌后，仅对受影响角色失效为UNKNOWN，不依据后台新牌牌面保持确定结论。公开可确定变化保留合法推理，死亡记录无可用资格。视图读取、AI评分、轮询不刷新；有UNKNOWN时“没有已知持有者”不等于“全场无人有”。

#### 5.14.3 无懈使用、保留、试探与诱骗

无懈决策比较当前锦囊负收益、击杀/死亡/关键控制、对方手牌、已知无懈持有者、己方反无懈与后续更高价值响应窗口。不使用会造成显著损失或关键击杀时提高使用意愿；当前牌价值低且后续威胁更高时倾向保留。低成本锦囊可在后续高价值锦囊存在、探明或消耗无懈的收益高于诱饵损失且无明显反效果时用于试探/诱骗；第一张只用先验概率，第二张起才可利用已观察到的读条。收益阈值属于可调参数。

### 5.15 单牌目标与多人牌理性策略

**状态：分析约定**

1. **【五谷丰登】选牌与使用**：不设永久总排序。优先考虑能攻击主要目标的距离牌、技能依赖而当前缺少的【杀】、当前高收益锦囊和救援/阻止敌方救援所需的【桃】；可靠队友在后续可安全取得桃时可让牌。使用前按当前存活角色环计算取牌顺序；自己取牌后至己方下次取牌前有两名敌人连续取牌、己方无无懈且敌方净收益明显更高时通常不用，关键翻盘或即时击杀除外。
2. **【借刀杀人】应答**：分别记录使用者、被借刀者和指定杀目标。队友确需武器时通常不出【杀】让其取得；敌方借刀且目标为敌人时通常出杀保留武器；目标为队友时比较1点伤害、卖血/反伤/濒死风险与失去武器的损失。诸葛连弩能支持当前高额爆发时显著提高出杀保留武器的价值。
3. **防御牌保留**：无法完成击杀或重大交换时，不为低收益火攻、技能弃牌或转化过度消耗【闪】【桃】等防御牌；能立即击杀、阻止己方死亡、形成明显人数优势或转化收益显著更高时可以支付，不能绝对禁止。
4. **【顺手牵羊】【过河拆桥】**：先移除己方判定区的危险延时锦囊，再处理主要目标的+1坐骑和有效防具、依法已知的桃/无懈、敌方高价值武器与-1坐骑。敌方连弩已具爆发条件时武器可动态升至更高优先级；对当前攻击方式无效的防具降级。只用合法可见信息。
5. **【乐不思蜀】**：评分包含基础威胁、预计跳过出牌阶段损失、`手牌数-手牌上限` 的弃牌损失、即将行动加分和判定前被移除风险。首个即将行动敌人初值加 `0.8` 至 `1.2`；第二目标虽强但更可能在判定前被拆顺时扣分。
6. **【兵粮寸断】**：手牌低于4张每少1张初值加 `0.15` 至 `0.25`，首个即将行动敌人加 `0.5` 至 `0.8`；高度依赖正常摸牌者加分，额外摸牌多或不依赖摸牌阶段者减分，同时扣除判定前被移除风险。合法目标仍必须满足实际距离为1。
7. **【桃园结义】与AOE**：统一比较敌方预期损失、击杀价值和己方受伤收益，扣除己方损失、队友濒死、敌方卖血和救援成本。桃园会使主要目标脱离击杀线或团队净收益为负时通常不用；南蛮/万箭有击杀可能且己方成本可接受时使用，队友可能先死亡、敌方卖血收益过高或单体集火明显更优时降低意愿。连续结算中胜利成立后停止未开始目标。

上述目标权重、无懈阈值、诱骗阈值、AOE净收益阈值、借刀武器价值换算、五谷同价值牌排序、隐藏手牌概率及延时锦囊行动修正均为可调计算参数。模拟必须输出实际采用值和关键决策原因，不等待不存在的“官方唯一正确AI策略”。

#### 5.17.2 斗地主身份等权与适性修正

**状态：分析约定**

每名武将分别保留地主原始胜率 `L`、农民原始胜率 `F`，并计算原始身份等权分：

`S_raw = (L + F) / 2`

只有技能结构明确不适合某一身份时，才启用身份适性修正：

- 只适合农民：`S_selectable = 0.9 * F`；
- 只适合地主：`S_selectable = 0.9 * L`。

“降低10%”是乘以0.9，不是减去10个百分点。即使启用适性修正，报告也必须继续分别列出 `L`、`F`、`S_raw` 和修正后的 `S_selectable`，不得用修正分覆盖原始结果。

未启用身份适性修正时，`S_selectable = S_raw`。

若某武将的技能结构使其整个斗地主模式均不适合：

- 不进入斗地主可选身份池；
- NPC不在斗地主登场；
- 其余每个大模式的综合评分分别乘以0.9，作为模式覆盖不足惩罚。

身份适性判断、排除理由和惩罚是否启用必须写入报告；没有技能结构证据时不得自行启用。

**AI策略**

1. 【阻进】按每个全局角色回合、转换后的【杀】【闪】【无懈可击】三个牌名分别保存一次额度。王经受伤后提高基本牌的防御转化价值，不无脑消耗最后一张【桃】或关键防御牌。

### 5.20 统一AI武将与反制规范V2.2

**状态：分析约定**

本节是当前统一策略入口。它继承第5.13至5.19节仍有效的目标、救援、信息和专项策略，只补充候选动作、动态估值、反制与审计要求，不改变任何技能的合法时机、目标、费用、次数或结算。旧模拟摘要没有因本节写入而重新运行。

#### 5.20.1 合法候选与策略选择

1. 规则层先生成全部合法目标、分支和动作，策略层再评分；“可以发动”不能实现为必定发动，“一般不对敌人发动”不能把敌人永久移出候选。
2. 技能没有写“其他角色”或明确排除自己时，不得为简化AI擅自排除自己；不得以策略偏好删去任何合法目标或合法分支。
3. 每名参战武将的策略画像至少允许记录：`core_plan`、`core_resources`、`skill_synergies`、`card_synergies`、`power_spikes`、`failure_states`、`hold_rules`、`activation_rules`、`action_order_rules`、`identity_adjustments`、`seat_adjustments`、`opponent_counterplay` 与 `audit_metrics`。简单武将只保存差异项；复杂武将还须说明核心循环、常见牌序、资源耗尽后的失败状态、高代价错误和合理反制。

#### 5.20.2 动态牌值与联动搜索

牌值按当前状态动态计算：

```text
动态牌值 = 基础用途价值
         + 技能联动价值
         + 牌序与计划价值
         + 击杀或救援价值
         - 机会成本
         - 资敌与反制风险
```

AI至少搜索“技能产生资源→另一技能或装备消费资源→伤害、摸牌、控制或再次产生资源→是否构成可持续循环”。【诸葛连弩】等装备必须结合具体武将、现有【杀】、行动窗口和后续牌序估值，不能只读取固定武器常数。

#### 5.20.3 响应与不响应候选

规则允许选择是否响应时，至少同时评价：使用或打出响应牌；不响应并承受效果；使用技能或装备提供响应；保留响应资源等待更高价值窗口。不得采用“有闪必闪”或“有无懈必无懈”。评分包括当前伤害或控制成本、响应牌机会成本、是否推进敌方技能计数或帮助其摸牌、是否打开青龙追杀或连续攻击、当前濒死与击杀风险，以及是否需要保留防御面对后续角色。

#### 5.20.6 沙摩柯专项策略

1. 高范围武器已完成本回合对应【蒺藜】触发后，其本回合档位价值已经兑现；此后重新比较原武器距离与技能、低范围武器即时价值、下回合更易触发的价值、提前暴露后的被拆风险，以及是否仍需原武器攻击远处目标。【诸葛连弩】支持连续输出、【贯石斧】可完成关键击杀或低范围武器能改善弃牌/牌序时提高换装权重，但攻击范围较低本身不构成必换理由，换装也不会让本回合补触发已经错过的低档计数。
2. 对手若要拆除其范围2以上武器且本回合计数仍为0，应比较“先使其实际使用或打出一张牌再拆”和“立即拆”的结果；仅对其使用【杀】而沙摩柯不使用【闪】，不会推进计数。还须检查其是否真的响应、拆后范围、无懈窗口、范围2时第二张无懈可能触发摸2，以及是否存在更直接的击杀。不可响应的技能拆取更适合该策略。
3. 设本回合已使用或打出数为`C`、当前攻击范围为`R`；当`C+1=R`且其大概率仍有合法响应牌时，普通试探和低收益攻击降权，优先不要求其使用/打出牌的伤害、失去体力、拆牌或控制。确定击杀、强控制或依法判断其没有响应牌时不降权；这是动态临界状态，不是永久低嘲讽。
4. 沙摩柯装备【青龙偃月刀】时，目标必须把“不使用【闪】并承受第一张普通【杀】”列为合法候选。第一击安全、未酒强化、无危险属性链、命中无高额追加收益、沙摩柯大概率有后续【杀】且出闪会把计数推进至范围3时，提高不闪权重，使青龙追杀条件不成立并避免连续响应助其摸3。伤害致命、酒杀/属性链危险、命中收益高、判断无后续杀、可稳定耗尽攻击资源或第一击本身已是临界触发牌时仍提高出闪权重。“非第一轮”只提高判断置信度，不是硬条件。

#### 5.20.7 曹纯版本化反制

设`L`为本局累计失去装备区牌数。当`L<=1`且没有更高威胁目标时，对手使用拆顺压低曹纯手牌具有额外价值，因为这会减少摸3后的筛选空间；可选择手牌时优先手牌，不无目的拆装备，装备离开会提高`L`并可能帮助成长。只有关键连弩、决定性防具、距离牌、即时击杀或关键控制时，才显著提高拆装备优先级。

旧版在出牌阶段开始时发动，行动前压手牌影响更稳定；新版可以先使用、装备或取得牌后再发动，能部分缓解。`L>=2`或曹纯已有多件低价值牺牲装备时，压低筛选空间的额外收益下降。该反制不得改写两个版本各自的发动时机和合法结算。

#### 5.20.8 张琪瑛【勾陈】决策纠错

【勾陈】发动后的三类牌按已确认规则分别随机获得：1张基本牌、1张锦囊牌、1张装备牌；AI没有选择类别或指定具体牌名的动作。策略只决定是否消耗“勾陈”：即时三牌收益通常使其倾向发动；只有保留标记对即将到来的【点化】深度、关键判定或生死牌堆顶控制非常重要时才考虑不发动，并同时估计短期弃置方块牌恢复标记的可能性。

审计至少保存`trigger_count`、`activation_count`、`skipped_for_topdeck_control`、`gained_basic`、`gained_trick`与`gained_equipment`；取得类别是随机结算结果，不得记成AI类别选择。

#### 5.20.9 清河公主专项策略

1. 在【谮构】已确认目标没有【杀】【酒】，目标只有一张可用【闪】，清河另有一张合法实体【杀】且无额外干预的限定场景，可评估“虚拟杀→虚拟酒→赋予闪诬→受酒强化的实体杀”序列：第一张虚拟杀被闪则后续酒杀造成2点；第一张不闪、后续酒杀被闪时，该【闪】属于使用牌并触发闪诬失去1点体力，加上前伤共损失2点；两次都不闪则共损失3点。因此该限定序列至少造成2点体力损失，不能把响应杀的闪误当成只打出而漏算诬。
2. 面对尚未发动【谮构】且即将行动的清河，提高对手保留最后一张【杀】的权重，以阻止其生成虚拟杀；适用于该杀当前只产生低收益、清河很快行动、自己可能成为高价值目标、只有一闪、清河可能有后续实体杀且不会因手牌上限白弃。当前杀可决定局势、存在连弩/多杀/属性链、清河已发动、行动很远、自己不可能成为目标或不使用将被弃置时，不应保留。不得固化为“面对清河永远保留最后一张杀”。
3. 审计记录虚拟杀酒组合尝试、稳定至少2点损失线路、对手保留/使用最后一杀，以及因目标已有杀名而阻断组合的次数。

#### 5.20.10 傅佥专项策略

1. 对手牌量不足以单回合填满【绝勇】并继续突破、不能长期积累爆发且自身有稳定防御/过牌/回复时，允许采用长期逼【破降】：每周期只投入最少数量的高压力实体单目标牌，迫使傅佥在承受结束阶段牌效与发动【破降】失去1体力之间选择，待其体力和容量下降后总攻。
2. 不在其下一出牌阶段前无脑投入多张高价值牌，因为一次【破降】会清除全部“绝”。优先投入结束阶段仍大概率合法、难以低成本响应、己方机会成本低且能造成实质伤害/控制/拆牌的牌；降低距离可能失效、同名延时锦囊已存在、重用几乎无效或属于总攻关键组件的牌。傅佥已经过出牌阶段时，可提高同周期多放“绝”的价值，同时必须计入其摸3后的反击。
3. 可按4至3体力运营压血、2体力储备填充和绕过手段、1体力进入高优先级突破窗口，但仍检查桃、酒、队友救援及【破降】新摸救援牌。傅佥本人不能见一张“绝”就自动发动，应比较“摸3、交牌、清绝收益－失去1体力成本”和结束阶段预计牌效；低压力、会自然失效或容易响应的“绝”可以保留，1体力且无可靠救援时大幅降低发动意愿。
4. 单挑中交牌只能资敌，逼降价值较高；团队模式可交队友并转化为团队反击，应降低长期逼降的默认收益并协调同周期投入，避免多张高价值牌被一次清空。

#### 5.20.11 吴文鸯专项策略

1. 【却敌】必须完整枚举只取得手牌、只弃基本牌加伤、背水两项并减少上限，以及不发动；背水必须与两个普通分支中的最佳方案比较，不能只判断背水本身是否正收益。
2. 设当前体力为`h`、上限为`M`，减少1点上限后`h'=min(h,M-1)`。`h=M`时当前体力同步下降1，成本最高；`h=M-1`时当前体力不变且背水后成为满体力；`h<=M-2`时当前体力不变但仍需评估未来回复空间和敌方击杀。低体力不是禁止背水的硬条件。
3. 满体力时，只有关键击杀并启动【仇决】、防止己方立即失败、同时夺关键防御牌并稳定命中、加伤产生决定性装备收益、形成连弩收割或显著改变胜负时，才显著提高背水意愿；普通多1伤、取得低价值牌或无关装备通常不足。
4. 装备转【杀】优先比较低机会成本材料、装备区有牌且能实际受伤的目标，同时计入击杀、卖血、闪概率、集火目标和目标存活后的装备收益，不能把“有装备”实现成永久优先。加伤可多造成1点、让存活目标多失去一件装备或跨击杀线触发【仇决】；直接击杀时不能把已随死亡离开的装备计入【冲坚】，必须比较“击杀与仇决收益”和“目标存活且取得装备收益”。
5. 背水按先取得手牌、再弃基本牌处理，因此新取得的基本牌可作材料；只需加伤或只需夺牌时，相应普通分支通常优于背水，只有两项均不可替代时提高背水意愿。不得因背水执行两项就无脑发动、因低体力永不发动、满体力为普通收益背水、牺牲不可替代装备只换普通1伤、把击杀目标装备计入冲坚，或认为【仇决】增加上限会自动恢复背水造成的实际体力损失。
6. 审计记录装备转杀、目标是否有装备、三个【却敌】分支、满体力背水与关键击杀、从存活者取得装备、击杀未取得装备及【仇决】后续。

#### 5.21.1 势·孙綝：类别清空、牌序与连环爆发

1. 核心循环为“整理手牌类别→建立【逆固】加伤→使用最后一张有目标的手牌→触发【戮连】并强制【乘势】→逐名结算铁索加伤→新牌重新建立类别”。不得把任一步实现为无条件发动。

3. 必须同时比较“先【逆固】后【戮连】”与“先【戮连】后【逆固】”：前者可让第一次【乘势】获得加伤但敌方交牌可能重新堵塞类别，后者可先兑现现有类别但第一次【乘势】没有该加伤。
